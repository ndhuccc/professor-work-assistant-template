# Bloom 層次測驗命題技能（精進版）

## 核心設計哲學

### 1. 多重選擇題為預設題型
多重選擇題（Multiple Correct Answers）比單選題的鑑別效果更高：
- **消除猜題效應**：單選 4 選項的猜對機率為 25%；多選題必須選出「所有正確答案」，猜對機率低於 6%
- **強制完整理解**：學生必須對每個選項獨立判斷，暴露部分理解的盲點
- **命題格式**：「以下哪些敘述正確？（可複選，選出所有正確答案）」

### 2. 創造層融入選擇題
創造層不等於「自由寫作」，選擇題也能測試創造思維：
- **設計策略識別**：「若要建構滿足 X 的物件，以下哪些設計策略有效？」（測試學生能否辨識多種合法建構路徑）
- **方案評估組合**：提供多種部分正確的設計方案，要求學生組合出完整解法
- **條件逆推構造**：給定目標性質，選出能推導出該性質的「充分條件組合」
- **設計的開放性**：正確答案可以不只一組，強制學生用「創造者的視角」而非「驗證者的視角」

### 3. Bloom 原則吻合說明要求
品質報告中每題必須明確回答：
> **「這道題強制學生執行了哪個認知動作？該動作的 Bloom 動詞是什麼？題目設計如何排除低層次的捷徑？」**

### 創造層多選題設計指引

創造層選擇題的核心：讓學生辨識「哪些策略能建構出符合條件的物件」，而非「哪個選項是正確的事實」。

**三種創造層多選題型：**

**型 A：設計策略識別**
```
「若要建構一個滿足[目標性質]的[數學物件]，以下哪些設計策略能成功達成？」
→ 學生必須在腦中執行「建構」並驗證，不是查找記憶
```

**型 B：充分條件組合**
```
「設計一個[物件]使其具有性質 P，以下哪些條件組合足以保證 P 成立？」
→ 學生需要判斷條件之間的蘊含關係，並組合出充分集
```

**型 C：缺陷修補**
```
「以下哪些修改能讓給定的設計 D 達到目標性質？（可複選，每個選項獨立評估）」
→ 強制學生以「設計者」視角評估每種修改的效果
```

## Phase 4：HTML 輸出（內建，可選）

使用者說「輸出 HTML」、「轉成 HTML」或規格中指定輸出格式為 HTML 時，
在 Phase 3 品質報告後直接輸出可用的互動 HTML，分為：

### 教師版（含答案、解析、鑑別度數據）
- 每題顯示正確答案 ✅
- 點展開可見「Bloom 原則吻合說明」與「鑑別度分析」
- 底部含全卷品質報告統計表

### 學生版（純題目，無答案）
- 多選題可勾選複選框
- 無答案提示
- 計時器（依規格設定的考試時間）
- 提交後顯示得分（選項全對得全分，部分正確得部分分）

**計分規則（多選題）：**
- 每題 N 個正確選項，正確勾選一個得 $\frac{1}{N}$ 分，誤勾一個扣 $\frac{1}{N}$ 分，最低 0 分

## 單題重命模式

使用者說「第 X 題鑑別度不足，重新設計」或「第 X 題太簡單」時：
1. 保持其他題目不動
2. 只重新設計指定題目（保持 Bloom 層次與覆蓋知識點不變）
3. 輸出新題目的完整區塊，更新全卷品質報告中對應行

## 附錄 B：Bloom 層次動詞庫（精進版）

每層次列出 10+ 標準動詞，命題時從中選取最精確的一個。

| 層次 | 標準動詞（選一個最精確的）| 識別指標 |
|------|----------------------|---------|
| **記憶** | 識別、回憶、列舉、定義、陳述、背誦、複述、命名、配對、描述 | 「死背可以答對」→ 確認是記憶層 |
| **理解** | 解釋、分類、舉例、比較、對比、摘要、推論、改述、詮釋、說明 | 「需用自己的話表達概念」→ 理解層 |
| **應用** | 執行、計算、實作、解題、操作、使用、套用、示範、產生、修改 | 「給公式/步驟，要求代入執行」→ 應用層 |
| **分析** | 區辨、組織、歸因、比較、推導、拆解、審查、整合、區分、偵測 | 「需拆解結構或推導隱含關係」→ 分析層 |
| **評鑑** | 判斷、批判、檢核、論證、評估、辯護、選擇、評價、合理化、反駁 | 「需用標準/準則做出判斷」→ 評鑑層 |
| **創造** | 建構、設計、規劃、生成、組合、創作、發明、假設、合成、改造 | 「需產生新的結構或方案」→ 創造層 |

**核心判斷問題（三層篩選）：**
1. 「死背就能答對嗎？」→ 是：記憶層；否：繼續
2. 「代入數字或已知程序可驗算嗎？」→ 是：應用層；否：繼續
3. 「需要比較、拆解結構，還是做出判斷，還是建構新物件？」→ 分析 / 評鑑 / 創造

### JSON 欄位規格

| 欄位 | 必填 | 說明 |
|------|------|------|
| `node` | ✅ | 對應知識節點名稱（雙語：中文 + 英文） |
| `question_type` | ✅ | 認知層次英文標籤：Knowledge / Comprehension / Calculation / Implementation / Analysis / Evaluation / Creation |

| `correct_answer` | ✅ | 正確選項標籤串接，例如單選 `"A"`，多選 `"ACD"` |

### explanation 品質要求（核心稽核項）

每題的 explanation 必須同時包含：
1. **正確選項的推理**：每個正確答案為何正確，提供數學推導、定義對照或邏輯步驟
2. **錯誤選項的迷思剖析**：每個干擾項對應的典型誤解，具體說明學生為何會選錯
3. **雙語呈現**：先中文後英文，格式為 `[解析（中文）] ... [Explanation (English)] ...`

## 品質紅線（命題禁止事項）

1. **禁止**干擾項只是隨意捏造的數字，每個選項必須對應真實迷思或真實正確概念
2. **禁止**分析層以上題目存在「代入數字即可驗證」的暴力捷徑
3. **禁止**全卷超過 20% 題目屬記憶層
4. **禁止**跳過 Phase 1 藍圖（含概念覆蓋地圖）直接出題
5. **禁止**跳過 Phase 3 品質報告直接結束
6. **禁止**省略每題的「Bloom 原則吻合說明」
