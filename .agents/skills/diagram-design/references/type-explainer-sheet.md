# Explainer sheet

**Best for:** teaching one algorithm, mechanism, or method on a single slide-sized page — *how it works* on the left, *proof that it works, with real numbers* on the right. Typical subjects: EM, gradient descent, backpropagation, k-means, attention, a control loop, a protocol handshake.

Prefer **Flowchart** when the logic alone is the story and no worked data is needed. Prefer **Loop** when a shared hub accumulates state and nothing ever stops. Prefer **Architecture** for a static system snapshot. Choose the Explainer sheet when a reader would otherwise ask "fine, but what does one pass actually do to real data?"

This is a **composite type**: one canvas, two panes, a header, and a footer strip. It borrows its mechanism grammar from Flowchart and its evidence grammar from the chart types. Numbers on the sheet are computed, never typed (§5).

Reference render: `assets/example-explainer-sheet.html` (EM on a two-component Gaussian mixture, regenerated by `scripts/build-explainer-sheet-example.py`).

## 1. Anatomy (default `slide-16x9`, viewBox `0 0 1280 720`)

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ TITLE: a claim, not a topic (40)                                         │
│ English / formal name (mono 12)                    one-line mnemonic →   │
├────────────────────────────┬─────────────────────────────────────────────┤
│  MECHANISM pane            │  EVIDENCE pane                              │
│  x 40–460                  │  x 508–1240                                 │
│                            │                                             │
│  [input]                   │  1. before / after small multiples          │
│     ↓                      │  ────────────────────────────────────       │
│  [focal step]  ← accent    │  2. the hidden variable made visible        │
│     ↓                      │  ────────────────────────────────────       │
│  [step]                    │  3. convergence / outcome sparkline         │
│     ↓                      │                                             │
│  <test?> → (Stop)          │                                             │
│    ↑___ loop back          │                                             │
├────────────────────────────┴─────────────────────────────────────────────┤
│ how to read the marks (left)               honest limit / caveat (right) │
└──────────────────────────────────────────────────────────────────────────┘
```

| Zone | Geometry | Content |
|---|---|---|
| Header | title baseline y=84, subtitle y=112, rule y=128 | Takeaway title, formal name, mnemonic |
| Mechanism pane | x 40–460, nodes `x=84 w=312` | 4–6 nodes, one decision, one terminal |
| Divider | x=484, one hairline, y 148–640 | Never a box, never a fill |
| Evidence pane | x 508–1240 | 2–3 stacked panels, hairline between |
| Footer strip | rule y=660, text baseline y=692 | Mark key (left), caveat (right) |

The footer strip is the 60px legend strip every preset reserves. Nothing else lives below y=660.

## 2. Header rules

1. **Title is a claim.** "EM 演算法：輪流解兩個較容易的問題" tells the reader the point; "EM 演算法" only names the topic. Write the sentence the audience should leave with.
2. **Subtitle is the formal name** in mono 12, `muted`. It is where the English term lives, so the title can stay in the reader's language.
3. **Mnemonic, right-aligned**, 16px sans 500, `muted`: the whole method in one arrow ("先估「誰負責」→ 再調「怎麼解釋資料」"). If it needs a second line, it is not a mnemonic.
4. **CJK titles use the sans voice.** On a slide, a 40px Han serif title reads thin and a Han glyph in italic is faked by the browser. When the title is Chinese, Japanese, or Korean, set it in the `node-name` family at weight 600, not Instrument Serif. Latin-only titles keep the serif. Callouts follow the same rule: no italic Han, ever. Use upright sans 12 `muted`.

## 3. Mechanism pane

Nodes follow the Flowchart grammar (shape carries type; rectangles for steps, diamond for the test, pill for the terminal) with these additions.

### 3.1 Three-tier node text

Every step node carries up to three tiers, and only the first is mandatory:

| Tier | Role | Example |
|---|---|---|
| Name | `node-name` 16/600 | `E 步：軟分群 Expectation` |
| Formula | formula line, Geist Mono 14 | `r_nk = P(z_n = k | x_n, θ_old)` |
| Plain sentence | sans 12, `ink` | `固定參數，算每筆資料屬於各群的機率。` |
| Caveat note (focal node only) | sans 12, `muted` | `保留全部可能群別，不先指定唯一答案。` |

The formula tells the expert what is computed. The sentence tells everyone else what it means. Drop the formula before dropping the sentence.

### 3.2 Iterate-until-converged pattern

A loop with a stopping test is a Flowchart, not a Loop (the path ends). Draw it as:

- Linear spine down the left pane, 40px gaps (presentation ramp).
- Decision diamond last, `是` exits right to a **Stop pill** (`rx=20`), `否` exits left.
- The `否` route is one rounded `r=8` elbow in `accent` that runs up the far-left margin (x=56) and re-enters the first loop node from its left edge. It never passes behind a node.
- The update that the back-edge performs (`θ_old ← θ_new`) is a 12px mono note under the diamond-left, not a label on the stroke. Strokes carry one-glyph labels only.
- Labels `是` / `否` use the Chinese register switch (12px sans 500 on a 24×16 paper mask) per `style-guide.md § Traditional Chinese labels`.

### 3.3 Budget

≤ 6 nodes including the terminal, ≤ 5 connectors, 1 focal node (accent fill + border). The input node is `backend` treatment (white), not `input`: on a sheet the first box is part of the loop's story.

## 4. Evidence pane

Two to three panels, stacked, each opened by a **bold sentence heading** (16/600) that states what the panel proves. Hairlines (`rule`) separate panels. The pane answers three questions in order:

| # | Question | Panel grammar | Example |
|---|---|---|---|
| 1 | What changed? | **Small multiples**, before | after, identical axes and scale | density curves before θ⁽⁰⁾ and after θ⁽¹⁾ |
| 2 | What is the hidden quantity? | **Proportion strip**, one bar per item, value beneath | responsibility r_n1 per point |
| 3 | Does it converge? | **Sparkline** with start/end values and iteration count | log-likelihood, 15 iterations |

Rules that make the panels honest:

1. **One worked example, reused.** Every panel draws from the same data (the line `X = {…}` is printed once, above panel 1). Never switch examples between panels.
2. **Identical axes in a before/after pair.** Same x-range, same y-scale, same gridline. A reader compares position, so anything that moves the frame hides the change. Print the axis end ticks and one dotted reference line (`rule-solid`, `1,3`).
3. **Print the parameters under each panel** in mono 11 `muted`, two lines maximum. The picture shows the change; the numbers let an expert verify it.
4. **Encode, then key.** Heavy solid = the whole (mixture), thin solid and dashed = the parts, short ticks = raw data. The key goes in the footer, not in a floating legend box.
5. **Strip panels print the value under each bar** (two decimals). The bar gives the gist; the number is the audit trail.
6. **Sparkline shows endpoints, not every tick.** Label the start and end values, the axis name (`ℓ`), and the iteration count. One curve, `ink` 2.4.
7. **Focal echo.** If the mechanism pane's focal node is the E step, the evidence panel that shows the E step's output may take the same `accent` on its heading. That is one focal thread drawn twice, so it counts as 2 of the 2 allowed accent elements. Everything else stays `ink` / `muted`.

## 5. Numbers come from code

A worked example is only worth drawing if a reader could reproduce it. Therefore:

1. **Compute, never type.** Write a short script that runs the method on the example data, then template every printed value from its output. The reference build does this: the 8 points, the responsibilities, both parameter sets, and ℓ at iterations 0, 1, and 15 all come from `scripts/build-explainer-sheet-example.py`.
2. **Round only at print time**, to the precision shown (2 decimals for r, μ, σ², π; 3 for ℓ).
3. **Choose an example where the picture is obvious.** Small N (6–10 points), well-separated by eye, a visible change in one step. If one pass changes nothing visible, pick different data or a different initialization, not a bigger number of iterations.
4. **State the algorithm variant** beside the result (`標準精確 EM；小幅改善時停止。`) so a reader knows which stopping rule and which model the numbers belong to.
5. **Seeded and deterministic.** No `random` without a fixed seed. The same script run twice produces the same sheet.
6. In the final reply, report the values you verified (for example "r₁ = 0.89 … 0.09; ℓ₀ = −15.581 → ℓ₁ = −15.464 → ℓ₁₅ = −14.353") so the user can spot-check without opening the file.

If the user cannot supply data and the method has no obvious toy example, say so and use the simplest textbook case; do not invent measurements.

## 6. Footer strip

- **Left: how to read the marks**, 12px sans `muted`, one sentence. Encodes line weights, dash styles, and tick marks in words.
- **Right: the honest limit**, 12px sans 600 `ink`, one sentence. Every method has one: "依賴初始化；可能停在局部解，不保證全域最優。" Put it in `ink`, **not** `accent`; accent stays reserved for the focal thread.
- The caveat is mandatory. A sheet that only shows the method working teaches half of it.

## 7. Typography on a sheet

| Slot | Face | Size / weight |
|---|---|---|
| Title | `node-name` family, CJK → sans (see §2.4) | 40 / 600 |
| Subtitle, data line, parameters | Geist Mono | 12 / 11 |
| Panel heading | `node-name` | 16 / 600 |
| Node name | `node-name` | 16 / 600 |
| Formula line | Geist Mono | 14 (in node) · 12 (in panel), weight 500 |
| Plain sentence, notes, footer | Geist + CJK stack | 12 / 400 |
| Mark and chart annotation | Geist Mono | 11 |

Math notation (subscripts, superscripts, Greek, ℓ) follows [primitive-math-notation.md](primitive-math-notation.md). Han stays at 12 or above everywhere.

## 8. Complexity budget

| Limit | Rule |
|---|---|
| Mechanism nodes (incl. terminal) | 6 |
| Mechanism connectors | 5 |
| Evidence panels | 3 |
| Charts in one panel | 2 (a before / after pair) |
| Data items in a strip panel | 10 |
| Focal accents | 2, one thread |
| Text blocks on the sheet that are prose sentences | 8 |

Above these limits, split into a mechanism sheet and an evidence sheet. Do not shrink type: the presentation ramp stays at 16/12/11.

---

## 9. Anti-patterns

- Title that names the topic but states no claim.
- Mechanism pane and evidence pane using different examples.
- Before / after charts with different axes or scales.
- Numbers typed from memory or "looks right"; any value without a source in code.
- Caveat missing, or caveat coloured `accent` so it competes with the focal step.
- Italic Han callouts, or a serif Han title at 40px on a slide.
- A boxed card around each pane. Panes are separated by hairlines only.
- A floating legend box inside a chart. The key lives in the footer strip.
- More than three tiers of text in a node.

## 11. Bilingual sheets (Traditional Chinese + English)

When the user asks for 繁體中文／英文雙語, keep the layout and double only the words. Chinese leads, English glosses. Learned from the Bayesian-density sheet, which needed about twice the text of the monolingual one.

| Slot | Chinese | English |
|---|---|---|
| Title | 40/600, line 1 | 16/500 `muted` sentence on line 2, left; same claim, not a literal transliteration |
| Mnemonic (right) | 16/500 on the title baseline | Geist Mono 12, one line below, same arrows |
| Node name | one line, both languages when the term is standard (`先驗 Prior`) | in the same line |
| Node sentence | 12/400 | 11/400 `muted` on the next line, ≤ 50 characters |
| Panel heading | 16/600 | 12/400 `muted` on the next line (in `accent` if the heading is accent) |
| Chart title | 14/600 | 11 `muted` on the next line |
| Footer key and caveat | 12 on y=684 | 11 on y=702, both within the 60px strip |

Rules:

1. **Formulas, numbers, axis ticks, and symbols are not translated.** They are the common language of both readers.
2. **Never shrink to fit.** Han stays at 12 or above and English at 11 or above. If a block overflows, cut a sentence (usually the second caveat), widen the label column, or drop the node's note tier. Add height by giving each node one more line, not by squeezing gaps below 40px.
3. **Budget the vertical axis first.** Each bilingual sentence costs one extra line (about 16px). Recompute node heights (A 72, steps 100, test diamond 88) and the gaps before drawing, then move the back-edge and its labels to the new y values.
4. **Short connector labels.** A full `是 / Yes` does not fit on a 56px segment. Use `是 Y` and `否 N` on a 32 × 16 mask.
5. **English glosses for symbols use the same tspans**: write `τ_N²` as `τ` + sub `N` + `²`, never a literal underscore.
6. **Mixed lines** (a Han sentence with a Latin symbol) stay in the sans voice. Mono is only for formulas and readouts.
7. **Accessible name stays short.** The SVG `<title>` is at most 60 characters, so put the bilingual title in the visible text and use `貝氏密度估測 Bayesian density estimation` style for the `<title>`; the long English claim goes in `<desc>`.
8. **Report both languages' numbers once.** The two lines say the same thing, so a printed number appears in the Chinese line only.

## 10. Pre-output checks specific to this type

- [ ] Title states a claim; subtitle holds the formal name; mnemonic fits one line?
- [ ] Mechanism ≤ 6 nodes, back-edge is one `r=8` accent elbow in the margin, no transit behind a node?
- [ ] Every printed number traces to the build script, and I can quote 3–4 of them in the reply?
- [ ] Before / after pairs share axes, scale, and reference line?
- [ ] Footer has both the mark key and the honest limit, the caveat in `ink`?
- [ ] No italic Han; Han ≥ 12px; formulas in mono with sub/superscripts via `dy`?
- [ ] Accent on ≤ 2 elements, both the same focal thread?
- [ ] If bilingual: Chinese leads, English glosses at 11 or above, formulas untranslated, `<title>` 60 characters or fewer (§ 11)?
- [ ] Bottom 60px holds only the footer strip; `min-width` equals 1280 and the SVG sits in a local scroller?
