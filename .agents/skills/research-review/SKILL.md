# 研究生進度、論文與 GitHub 證據審查

## 輸入
指定研究生／專案、週報或論文版本、本週範圍、前次教授建議與回覆、指定來源及私人目的地。

## 程序
1. 讀 AGENTS.md、docs/QUALITY.md、docs/PRIVACY.md。核對專案與學生對應，不處理無關資料夾。沒有私人目的地先只做來源盤點。
2. 讀教授原始修正清單、學生逐項回覆及本次文件／程式／實驗證據。對照同一項需求，不能只根據學生說「已完成」就通過。
3. 逐項核對：教授要求 → 學生主張 → 版本與實際段落／圖表／commit → 證據支持程度 → 仍需修正。
4. 實驗核對資料切分、baseline、超參數、隨機種子、指標定義、資料洩漏、可重現線索及結論範圍；未提供記錄不編造結果，也不擅自執行學生程式。
5. 保留跨週未結事項，區分研究完成與紀錄尚未上傳。沒有找到 commit 只說搜尋範圍與限制，不斷言沒有工作。
6. 以簡單語句撰寫：先說問題、指出來源、解釋影響，再給可執行的修改步驟；術語先定義。由教師決定研究方向與優先順序。

## 輸出與驗收
私人逐項審查表、跨週待辦、支持／矛盾證據、待教師決定事項與下一步。論文沒有讀到的部分列明，不泛稱全文已查核。
發 issue、通知學生或上傳評語須另列對象、內容、影響並確認。
