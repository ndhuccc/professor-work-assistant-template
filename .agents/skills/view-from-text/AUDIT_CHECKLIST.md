# 稽核清單(交付前逐項核對)

本清單彙整可攜版技能的所有稽核項目。每一項後面的括號是來源章節:

- `規格` = `AI_AGENT_FILE_FORMAT_SPEC.md`
- `版面` = `VISUAL_AND_LAYOUT_GUIDE.md`
- `設計` = `PRESENTATION_DESIGN_GUIDE.md`

優先順序:格式規格(會不會被拒絕匯入)> 版面規範(設計品質)> 自行判斷。

---

## A. 格式硬規則(違反會導致整批拒絕匯入)(規格「驗證規則與常見錯誤」1–15)

- [ ] A1. `schemaVersion` 為 `3`;`rootSceneId` 對應的 Scene 存在,且其 `parentFrameId` 為 `null`。
- [ ] A2. 每個 Scene 的 `camera.zoom` 為有限數字且 > 0;`camera.x`、`y`、`rotation` 為有限數字。
- [ ] A3. 每個 Scene 的 `nodeIds` 列出的每個 id 都存在於 `nodes`,且該節點的 `sceneId` 等於此 Scene 的 `id`(雙向一致)。
- [ ] A4. 一個節點只屬於一個 Scene(不可同時出現在兩個 `nodeIds`),且不是孤兒(每個 `nodes` 的 id 都被某個 Scene 的 `nodeIds` 引用)。
- [ ] A5. 每個節點的 `transform.x`、`y`、`scaleX`、`scaleY`、`rotation`、`width`、`height` 都是有限數字;`width`、`height` > 0;`scaleX`、`scaleY` 不為 0。
- [ ] A6. `type: "frame"` 的節點有合法的 `frame` 內容;`frame.childSceneId` 指向的 Scene 存在,且其 `parentFrameId` 等於此 Frame 節點的 `id`。
- [ ] A7. `type: "image"` 有非空的 `image.src`;`type: "video"` 有非空的 `video.src`;`type: "embed"` 有合法的 `embed.url`。
- [ ] A8. `type: "connector"` 的 `sourceNodeId`、`targetNodeId` 都存在、都與此 Connector 同屬一個 Scene、都不是 Connector 本身、且彼此不同;`sourceHook`、`targetHook` 為 0–15 的整數。
- [ ] A9. Scene 透過 `parentFrameId` 往上追溯時不會形成循環。
- [ ] A10. 每個 Step:`id` 非空字串;`label` ≤ 200 字;`durationMs` 在 180–10000;`holdMs` 在 0–30000;`easing` 為 `linear`、`easeInOut`、`smooth` 之一;`speakerNotes`(若有)≤ 20000 字。
- [ ] A11. 每個 Step 的 `target.sceneId` 存在;`target.kind` 為四種合法值之一。
- [ ] A12. `scene-point` 的 `point.x`、`point.y`、`zoom` 為有限數字,且 `zoom` > 0。
- [ ] A13. `focus-node` 的 `nodeId` 存在,且該節點的 `sceneId` 等於此 Step 的 `target.sceneId`。
- [ ] A14. `enter-frame` 的 `frameId` 存在,`type` 為 `"frame"`,且該節點的 `sceneId` 等於此 Step 的 `target.sceneId`。
- [ ] A15. `reveal.enter` 與 `reveal.exitNodeIds` 列出的每個節點,都與此 Step 的 `target.sceneId` 屬於同一個 Scene。

## B. 不會報錯,但會讓畫面明顯出錯(規格)

- [ ] B1. Connector 的 `style.textColor` 使用深色(Connector 標籤底是近白色卡片)。
- [ ] B2. 非矩形 `shapeKind`(`star`、`diamond`、`pentagon`、`triangle`、`ellipse`、`arrow`)裡沒有放長文字。文字另外用獨立的 `text` 節點放在旁邊。
- [ ] B3. `scene-point` 的 `zoom` 與 `point` 讓要呈現的內容貼齊瞄準框,沒有大片空白,也沒有裁到內容。
- [ ] B4. `metadata.aspectRatio` 有明確填寫(`16:9` 或 `4:3`)。
- [ ] B5. **每一個** `scene-point` 都有 `referenceViewport`,值等於頁面參考尺寸(16:9 為 1280×720,4:3 為 960×720)。程式逐一檢查,不可省略(省略時 `zoom` 不隨播放視窗縮放,視窗大於參考尺寸時會露出相鄰頁)。
- [ ] B6. 鏡頭已為 Frame 標題列留空白:`zoom = H/(H+100)`、`point.x` = 頁面左上 x + W/2、`point.y` = 頁面左上 y + H/2 − 50;頁面頂端 100 單位(`y < 0` 的部分)沒有任何節點;Frame 標題為單行。公式見設計準則「頁面排列與鏡頭公式」。
- [ ] B7. 同一個 Scene 內相鄰頁的橫向間隔 ≥ 160(`pitch ≥ W + 160`),鏡頭左右多看到的範圍(約 89 或 67 單位)不會露出相鄰頁。已用 Player 以 1280×720 與 1920×1080 各播一次確認:每頁(`scene-point` 停點)填滿畫面、看不到相鄰頁、頁面標題完整位於 Frame 標題列下方。根層聚焦 Frame 的 step 的 reticle 剛好框住該 Frame、沒有框進隔壁 Frame。
- [ ] B8. Connector 的 `style.stroke` 不透明且與畫布有對比,線寬明確設定(例如 3);在實際播放器核對線與箭頭可見。根場景連線須在縮小後的根場景檢查,頁內連線須在對應頁的正常播放鏡頭檢查;不得只數 JSON 節點。
- [ ] B9. **Frame 節點使用標準樣式**(`fill`/`stroke` 為 `transparent`、`textColor` `#f2ede4`、`fontSize` 22、`radius` 0;`frame` 只有 `childSceneId`、`previewMode`、`padding`、`clip`,**不設任何 title 開頭的欄位**);Frame 標題單行、≤ 16 字。自訂標題色曾造成對比過低、看不清楚(SKILL §4D;`audit_deck.py` 檢查)。

## C. 生成流程自檢(規格「給 agent 的產生流程建議」1–8)

- [ ] C1. 文本已拆成獨立的知識單元;跨單元的關係已記下,之後用 Connector 表達。
- [ ] C2. Scene 樹已規劃:一個根 Scene,每個一級單元對應根 Scene 上的一個 Frame 與一個子 Scene。所有 id 語意化命名(如 `frame-<單元>`、`scene-<單元>`、`<單元>-title`)。
- [ ] C3. 每個 Scene 的 Node 不重疊,留白合理;不同單元的排版盡量有差異。
- [ ] C4. 配色已依 D 節核對對比。
- [ ] C5. Step 結構:含 Frame 的 Scene(根 Scene 等)**每個 Frame 恰好一個 step**(以該 Frame 為中心的 `scene-point`);每個單元的子 Scene 每頁一個 `scene-point` step(必要時搭配 `reveal` 與 `initiallyHidden`),每單元至少 2–3 頁。**不用 `enter-frame`、不寫開場 `scene-overview`、不寫「返回總覽」。**所有 Step 依深度優先「Frame 1 → 單元 1 的頁面 → Frame 2 → …」串成一個扁平陣列,`order` 依序遞增。
- [ ] C6. 完整 JSON 含 `schemaVersion`、`rootSceneId`、`scenes`、`nodes`、`steps`、`metadata`。
- [ ] C7. 已用程式邏輯逐條核對 A1–A15,特別是 Scene↔Node 雙向、Frame↔子 Scene 雙向、Connector 參照與 hook 範圍、reveal 節點與目的地同 Scene。
- [ ] C8. 輸出為純 JSON 檔案,方便存成 `.json` 後用 Open 匯入。

## D. 拆頁與內容預算(版面 §1)

- [ ] D1. 每頁都能寫出一句問句,問句的答案就是頁面標題(版面 1.1)。寫不出或寫出兩個,就重新切分。
- [ ] D2. 頁面標題是結論句,6 到 20 個中文字(版面 1.3)。
- [ ] D3. Step 的 `label` 是結論短句,≤ 20 字,**不加序號前綴**(時間軸卡片已自動顯示編號;版面 1.3)。所有單元的 `label` 格式一致。
- [ ] D4. 每頁的內容預算(版面 1.2):
  - 主視覺 1 個。
  - 次要文字塊 ≤ 3 個。
  - 獨立公式區塊(`$$`)≤ 2 個,整頁 ≤ 6 個(行內公式不限)。
  - 條列 ≤ 4 項,超過改用表格或拆頁。
  - 正文 ≤ 120 個中文字,不含標題、公式與英文行。**超過就拆頁,不刪內容**(SKILL §3A)。
  - 字級:標題 ≥ 40、正文 ≥ 22、次要 ≥ 18;任何文字不低於 16。
- [ ] D5. 符合任一拆頁條件就拆(版面 1.4):出現第二個主視覺;獨立公式區塊超過 2 個;正文超過 120 字;「先…再…」的時序且兩段都需要視覺;同頁同時含新概念與應用例。
- [ ] D6. 只有兩頁各佔不到 30% 面積,或互為一問一答時才合併(版面 1.4,後者用問答版型 M)。
- [ ] D7. 教學內容的頁型順序不顛倒(版面 1.5):開場問題 → 定義 → 直覺/圖像 → 推導 → 數值驗算 → 對比或易錯 → 練習 → 口訣與承先啟後。
- [ ] D8. 每 3 到 4 頁至少有一張「視覺休息頁」(版型 N 或 P)(版面 1.5)。
- [ ] D9. 保留原文的比喻、口訣、數值例、習題;不另造(版面 1.6.1)。
- [ ] D10. 不改數字。若原文公式損壞,先還原,再重新演算每個數值(版面 1.6.2)。
- [ ] D11. 習題附提示、不附完整答案,除非原文有或使用者要求(版面 1.6.3、SKILL §3D)。
- [ ] D12. 原文的警告與易錯點單獨成頁或單獨成卡(版面 1.6.4)。
- [ ] D13. 講義中沒有的觀點不加入投影片(課程規則,見 SKILL.md §3)。
- [ ] D14. 頁面標題與英文副標都不含行內數學 `$…$`,兩者不重疊(SKILL §4C)。

## G. 示意圖(版面 §4)

- [ ] G1. 判定原生節點或 matplotlib 依 SKILL.md §4A:內容屬於「必圖」類(函數、機率密度、高斯曲線、等機率線、幾何、決策邊界、門檻、面積、統計資料)時必須用 matplotlib;只有「不需圖」類(數字表、公式對照、條列、卡片、流程、概念關係)才用原生節點(版面 4.1)。
- [ ] G2. 函數曲線、切線、向量等由公式計算,沒有手填座標(版面 4.1、4.4)。

## H. 簡報結構與構圖(設計)

- [ ] H1. 每個知識單元都是獨立的 Frame,有自己的子 Scene。
- [ ] H2. Frame 在外層只顯示標題與輪廓,細節都在子 Scene。
