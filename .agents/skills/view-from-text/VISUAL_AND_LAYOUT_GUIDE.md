# view-from-text 補充規範：拆頁、色彩、版型與示意圖解

> **定位**：這份文件補充 `SKILL.md`、`AI_AGENT_FILE_FORMAT_SPEC.md` 與 `PRESENTATION_DESIGN_GUIDE.md`，回答它們沒有規範的問題：**怎麼拆頁、用什麼顏色、選什麼版型、怎麼畫精準的示意圖**。
>
> **優先順序**：格式規格書（會不會被拒絕匯入）> 本規範（設計品質）> agent 自行判斷。本規範只在一處明確覆寫格式規格書，見第 4.6 節。
>
> **驗證狀態**：本規範的色彩對比數值、matplotlib 輔助程式（`jbd_figure.py`）和內嵌 SVG 的 image 節點，都已用專案的 `validateDocument()` 與匯入解析器實測通過。**尚未實測**的項目都標了「待驗證」，請在 App 裡確認後再把標記拿掉。

## 1. 拆頁標準

### 1.1 一頁只回答一個問題

動手設計前，先對每個候選頁面寫下一句問句：「這一頁要讓觀眾弄懂什麼？」

- 寫不出來，代表這頁沒有焦點，要重新切分。
- 寫出兩個，代表要拆成兩頁。
- 這個問題的**答案**就是頁面標題（見 1.3）。

### 1.2 內容預算（每頁）

> **預算是拆頁的觸發條件，不是刪減的理由。** 超過就拆頁或加續頁，不得刪掉講義有的定義、算式、說明、例子或附圖（`SKILL.md` §3A）。

| 項目 | 上限 | 說明 |
|---|---|---|
| 頁面標題 | 1 個 | 結論句，6 到 20 個中文字 |
| 主視覺 | **1 個** | 圖、表、公式卡、流程、數線擇一為主 |
| 次要文字塊 | ≤ 3 個 | 說明、提醒、補充 |
| 獨立公式區塊（`$$`） | ≤ 2 個 | 行內公式不限，但整頁不超過 6 個 |
| 條列項目 | ≤ 4 項 | 超過就改用表格或拆頁 |
| 正文字數 | ≤ 120 個中文字 | 不含標題、公式與英文行；超過就拆頁，不刪字 |
| 字級 | 標題 ≥ 40、正文 ≥ 22、次要 ≥ 18 | 任何文字都不低於 16 |

### 1.3 標題寫成結論，不寫主題詞

| 不好（主題詞） | 好（結論句） |
|---|---|
| 距離公式 | $g(\mathbf{x})$ 告訴你在牆的哪一側、離牆多遠 |
| 法向量 | 權重向量 $\mathbf{w}$ 是法向量，不是斜率 |
| 縮放的影響 | 方程式兩邊同乘 2，牆和距離都不變 |
| 注意事項 | 最容易搞混的兩件事 |

頁面標題之外，**Step 的 `label`** 也用結論短句（≤ 20 字），讓時間軸卡片可以直接當目錄。**不要加序號**：時間軸卡片已自動顯示編號，label 再寫序號會重複，而且各單元容易不一致。頁面上方 100 單位（`y < 0`）預留給 Frame 標題列，不放任何節點（鏡頭公式見 `PRESENTATION_DESIGN_GUIDE.md`「頁面排列與鏡頭公式」）。

### 1.4 拆頁與合併的觸發條件

**符合任一條就拆：**
1. 出現第二個主視覺。
2. 獨立公式區塊超過 2 個。
3. 正文超過 120 個中文字。
4. 內容有「先…再…」的時序，而且兩段都需要視覺（例如「推導」和「驗算」）。
5. 一頁同時含「新概念」和「它的應用例」。

**可以合併：**
- 兩頁各自只佔不到 30% 的面積。
- 兩頁互為一問一答、拆開後都無法獨立成立，可合併成「問答頁」（版型 M）。

### 1.5 教學類文本的頁型序列

下面是建議的骨架，不是每一頁都必須有，但順序不要顛倒：

> 開場問題 → 定義 → 直覺／圖像 → 推導 → 數值驗算 → 對比或易錯 → 練習 → 口訣與承先啟後

上面是**單元敘事弧**的簡化版;完整的敘事弧、頁間關係與銜接條規則見 `../NARRATIVE.md` §2、§3,它們是硬規則。

「視覺休息頁」（版型 N 大字頁或 P 圖文頁）**只在連續 5 頁以上都是文字密集頁時才可以插入**,而且必須有實質內容(一個結論、一張圖或一個口訣);不得為了湊頁數或湊規則加入重複或空洞的休息頁。

### 1.6 對原文的處理規則

1. **保留原作者的資產**：比喻（如戰機、雷達防禦牆）、口訣、數值例、習題，一律保留，不另造。
2. **不改數字**。若原文公式損壞（例如複製後被拆成一行一個符號），先還原，**還原後重新演算每一個數值**，再往下設計。
3. **習題附提示、不附完整答案**，除非原文有答案，或使用者要求（`SKILL.md` §3D）。
4. **原文的警告、易錯點**單獨成頁或單獨成卡，不要夾在別的內容裡。
5. **原文的附圖一律採用**，用同一份資料重畫成深色 SVG（`SKILL.md` §4F）。
6. **算式寫完整**：符號式 → 代入 → 中間結果 → 結果，每步附理由（`SKILL.md` §3B）。

### 1.7 中英對照的排版

規則見 `SKILL.md` §4C。排版時的做法:

| 項目 | 做法 |
|---|---|
| 標題區 | 標題 (60, 26, 1160, 60);英文副標 (60, 88, 1160, 38),24 px、`#b7b0a5`。頁面內容從 y = 130 起 |
| 卡片 | 中文行在前,英文行在後(斜體)。卡片高度要容納兩種語言,先估再用 `preview_deck.py` 的 slack 報告校正 |
| 字級 | 由大到小試:能放進框的最大字級,下限 22 px。英文行與中文行同字級 |
| 表格 | 表頭與列名兩行(中文、斜體英文),列高 ≥ 84;純數值格不翻譯 |
| 大字頁(N) | 中文兩行大字,英文兩行斜體接在下面,同一張卡 |
| 流程頁(G) | 卡片寬度與間隔要讓連線標籤(中文加英文)放得下,間隔 ≥ 80 |

## 2. 色彩語意

### 2.1 固定底色與角色色

畫布底色固定為 `#151513`。**角色色綁定概念，不當裝飾用**：

| 角色 | 色碼 | 用於 | 在畫布上的對比 |
|---|---|---|---|
| 一般文字 | `#f2ede4` | 標題、正文 | 15.7 |
| 次要文字 | `#b7b0a5` | 副標、圖說、提醒 | 8.5 |
| **主角／正側** | `#d97757` | 第一類、被判定為正、重點、主要產物 | 5.9 |
| **對照／負側** | `#6a9fd6` | 第二類、被判定為負、對照組 | 6.6 |
| **邊界／門檻** | `#e0995f` | 決策邊界、牆、閾值、分隔線 | 7.7 |
| **向量／方向** | `#5fb8a8` | 向量、切線、梯度、箭頭 | 7.8 |
| **警示／反例** | `#e07a70` | 易錯點、錯誤做法、不成立 | 6.3 |
| **成立／不變** | `#7dbb8c` | 正確結論、不變量、驗證通過 | 8.1 |
| Connector 標籤文字 | `#1c1712` | 只用在 Connector（標籤底是近白色） | 16.1（對白底） |

### 2.2 卡片填色

| 卡片類型 | `fill` | `stroke` |
|---|---|---|
| 中性卡 | `rgba(245,241,233,0.05)` | `rgba(245,241,233,0.20)` |
| 角色卡 | 角色色的 `rgba(…,0.12)` | 同色的 `rgba(…,0.65)` |

角色色的文字放在對應角色卡上，對比仍在 **4.9 以上**（實測：主角色在橘色卡上 4.9，其他更高）。

### 2.3 使用規則

1. **一概念一色，全份簡報一致。** 第 1 頁橘色代表正側，第 4 頁就不能拿橘色代表別的東西。
2. **每頁最多 4 種角色色加中性色。** 色彩多了反而沒有語意。
3. **不單靠顏色傳達意義。** 角色卡要附文字標籤或符號（`+`／`−`、`✓`／`✗`、「正側」／「負側」）。
4. **青綠（向量）與綠（成立）色相接近**，色覺差異者難以分辨，**不要放在同一個圖裡**，非放不可時一定要加文字標籤。
5. **文本沒有「正／負」概念時**，把角色色對應到「主角／對照／邊界／輔助／警示／成立」，並在簡報第一個內容頁就決定好，之後不變。
6. **背景一律不另設**，不要替整頁填滿底色。需要分區，用中性卡。
7. 所有文字與其**實際合成後的背景**（含半透明卡片疊色）對比 ≥ 4.5:1，以程式計算為準，不憑肉眼。

## 3. 版型庫

以下座標都是 **1280×720 頁面的本地座標**。每頁先選主版型，再按需要加次要元素。

### 3.1 版型一覽

| 代號 | 版型 | 適用的內容關係 | 骨架（x, y, w, h） | 注意事項 |
|---|---|---|---|---|
| **A** | 公式卡 | 定義一個核心公式 | 標題 (60,34,1160,66)；卡 (200,160,880,260)；說明 (200,450,880,120) | 公式字級 ≥ 34，卡內只放一個 `$$` |
| **B** | 左右對照 | 兩個概念比較、前後比較 | 左卡 (60,130,570,520)；右卡 (650,130,570,520) | 兩邊用兩種角色色，標題對稱 |
| **C** | 三欄並列 | 三個同類項目 | 三卡各 (60/450/840,160,380,420) | 三卡高度一致，條列各 ≤ 3 項 |
| **D** | 步驟推導 | 逐步推導、數值例的完整算式 | 左側 3 張疊卡 (60,120,700,~130)，右側圖 (800,120,420,568) | 步驟用 ①②③ 編號，最後一張卡用主角色強調結論 |
| **E** | 對照表 | 多個物件 × 多個屬性 | 表頭列 (…,135,…,52)；資料列間距 96、高 80 | 重點列用「成立」色卡；表格 ≤ 4 列 × 4 欄 |
| **F** | 數線 | 數值大小、位置、正負側 | 線 (100,~620,1100,4)；標記 8×60 | 標記按**比例**定位（見 3.2），不是等距 |
| **G** | 流程箭頭 | A→B→C 順序流程 | 3 到 5 個卡橫排，Connector 連接 | 卡寬一致，Connector 用 `hook 4 → 12` |
| **H** | 循環／迴圈 | 迭代、回饋 | 4 個節點排成菱形，4 條弧形 Connector（`curve: true`） | 節點 ≤ 5 |
| **I** | 層級樹 | 分類、包含關係 | 根 (540,130,200,70)；子層橫排；Connector 由上而下 | 深度 ≤ 3，每層 ≤ 5 個 |
| **J** | 時間軸 | 歷史、版本、階段 | 水平線；里程碑圓點；上下交錯放標籤 | 里程碑 ≤ 6 個 |
| **K** | 金字塔／漏斗 | 層次、篩選 | 4 到 5 個矩形，寬度遞減並置中 | 矩形內放文字；**不要用三角形形狀放字** |
| **L** | 主副配置 | 有主有次的重要性差異 | 主卡大 (60,150,680,500)；2 到 3 張副卡 (780,…,440,~150) | 面積比至少 2:1，才看得出主次 |
| **M** | 問答／練習 | 習題、思考題 | 左：題目卡；右：提示或思路卡 | 答案不放在同一頁，除非使用者要求 |
| **N** | 大字／口訣 | 收尾、金句、口訣 | 一張置中大卡 (60,120,1160,250)，字級 ≥ 40 | 全頁只有這一個焦點 |
| **O** | 程式碼頁 | 程式範例 | 深色卡 (60,130,1160,~450)；`fontFamily: "Consolas"`，`fontSize` 20 到 22 | 一頁 ≤ 14 行；長度更長就拆頁 |
| **P** | 圖文並排 | 一張 matplotlib 圖加要點 | 圖 (60,130,600,560)；右側 2 到 3 張文字卡 (700,…,520,~160) | 圖框與圖的長寬比一致（見 4.3） |
| **Q** | 前後對比 | 處理前後、改進前後 | 左卡、中間 Connector（箭頭）、右卡 | 左用對照色，右用主角色 |
| **R** | ✗／✓ 對照 | 常見錯誤對正確做法 | 上下兩列，各一張卡；左側用 ✗（警示色）、✓（成立色） | 每張卡 ≤ 2 句話 |
| **S** | 大數字 | 單一關鍵指標 | 數字 (60,200,600,200)，字級 ≥ 96；右側 1 到 2 句說明 | 數字旁必須有單位與意義 |
| **T** | 四象限 | 兩個維度的交叉分類 | 2×2 網格各 (60/660,130/400,560,250)；軸標籤 | 四格各用不同角色色，但標籤要寫清楚 |

### 3.2 數線的比例定位公式

數線上的位置要按數值**成比例**，才不會誤導觀眾。令數線從 $x_0$ 起、每單位 $s$ 像素，數值 $v$ 的位置為：

$$
x(v)=x_0+s\cdot v
$$

例如第 4 頁的例子：原點在 $x=300$、每單位 400 像素，則 $g=-0.05$ 的位置是 $300-0.05\times400=280$，離牆只有 20 像素，一眼就看得出「很小但仍在負側」。

| 這一頁的內容是… | 用哪個版型 |

| 兩個東西比較 | B（或 Q、R） |
| 三個並列的同類項 | C |
| 一步步推導 | D |
| 多物件多屬性的數字 | E |
| 數值的大小與位置 | F |
| 有先後的流程 | G |
| 會重複的迭代 | H |
| 包含或分類關係 | I |
| 歷史或階段 | J |
| 逐層篩選 | K |
| 有主有次 | L |

| 金句、口訣、收尾 | N |

### 3.4 避免單調的規則

1. **相鄰兩頁不用同一個主版型。**
2. **同一份簡報有 5 頁以上時，至少用 4 種不同的主版型。**
3. **同一版型連續出現不超過 2 次**（整份簡報中可重複）。
4. 同一個版型每次出現時，要換一種**角色色組合**或**排列方向**（例如 C 的三欄換成 B 的左右）。
5. **圖示形狀要有語意**：`star` 能量或光，`ellipse` 液體或群體，`diamond` 分子或判斷，`arrow` 流動；**形狀裡不放字**，文字另外用獨立節點。
6. **形狀、尺寸、位置都不要完全對稱**：用大小表示重要性，留一點不對稱的呼吸感。

## 4. 示意圖解的生成方法

### 4.1 什麼用原生節點，什麼用 matplotlib

判斷標準只有一個：**圖上的位置、大小、角度、形狀是否承載資訊？**

| 圖的性質 | 做法 |
|---|---|
| 概念圖、流程、層級、卡片、時間軸（位置只是排版） | **原生節點**（shape、text、Connector），可以直接編輯 |
| 幾何（向量、直線、角度、垂直、投影、面積） | **matplotlib** |
| 函數圖形（曲線、切線、極值、積分區域） | **matplotlib** |
| 統計圖（直方圖、散佈圖、盒鬚圖、分布曲線） | **matplotlib** |
| 決策邊界、特徵空間、網格上的區域 | **matplotlib** |
| 示意性質、位置不準也無妨的「概念草圖」 | 原生節點，並在圖說標明「示意」 |

**絕對不要手填座標去「畫」一條函數曲線**，要用公式計算。

### 4.2 公式一律用 LaTeX 渲染

| 位置 | 做法 |
|---|---|
| 原生 text 節點 | `$…$` 行內、`$$` 區塊（KaTeX）；向量用 `\mathbf{w}`；範數用 `\|\mathbf{w}\|`，**不要用 `||`** |
| matplotlib 圖內 | **mathtext**，並設 `mathtext.fontset = "cm"`（Computer Modern，外觀接近 LaTeX，不需安裝 TeX） |
| `usetex=True` | **預設不用**。只有確認執行環境有完整 TeX，且 mathtext 無法表達時才用 |

公式的字母符號全篇一致：向量粗體 `\mathbf{}`，純量斜體，矩陣大寫粗體。

### 4.3 matplotlib 的繪圖規範

使用輔助程式 `jbd_figure.py`（隨本規範附上），它已內建以下規則：

1. **圖的尺寸與 image 節點等比。** `figsize = 節點寬 / 100, 節點高 / 100`，也就是 **1 英吋 = 100 節點像素**。
2. **字級換算**：`font_pt = font_px × 0.72`（`px_to_pt()`）。圖內文字要與頁面文字級別一致，不要比頁面正文小。
3. **背景透明**，色彩一律取自 2.1 的調色盤。
4. **輸出 SVG 並設 `svg.fonttype = "path"`**：文字轉成外框，使用者端不需要任何字型，畫布無限縮放也不糊。
5. **不要用 `bbox_inches="tight"`**，它會改變長寬比，圖與節點框就對不上。
6. **邊界以像素指定**（預設左 96、下 76、右 24、上 24）。含軸標籤時，左邊界 ≥ 90、下邊界 ≥ 70。
7. **渲染前自動檢查有沒有內容被切掉**（`check_not_clipped()`，`svg_data_uri()` 會自動呼叫）。這一步在實測中抓出過軸標籤被裁掉的錯誤。

### 4.4 精準度規則

| 情況 | 規則 |
|---|---|
| 涉及方向、角度、垂直 | **必須** `ax.set_aspect("equal")`，否則垂直看起來不垂直 |
| 直角 | 畫直角符號（小方塊），不要只靠「看起來垂直」 |
| 向量、法向量、垂足 | 用**解析式計算**（例如垂足 $= -w_0\mathbf{w}/\|\mathbf{w}\|^2$），不要手填座標 |
| 函數曲線 | `np.linspace` 取 **≥ 400 點** |
| 切線 | 用導數解析式算斜率，不用差分近似 |
| 統計圖 | `np.random.default_rng(seed)` **固定亂數種子**，並在圖說標示樣本數 $n$ |
| 資料點很多（> 500） | 散佈圖用 `rasterized=True`，避免 SVG 過大 |
| 座標範圍 | 明確設定 `set_xlim`／`set_ylim`，不要用自動範圍 |
| 圖例 | 放在空白角落（例如 `loc="lower right"`），**渲染後目視確認沒有壓到曲線或軸線** |
| 垂直參考線 | 用 `ax.vlines(x, 0, 0.75 * ymax)` 限高,不要用貫穿整張圖的 `axvline`;圖例放在頂部空白帶(`loc="upper center", ncol=n`),避免與參考線、曲線重疊 |
| 數值要與正文一致 | 圖中的點、截距、斜率必須用**與正文完全相同的數字** |

### 4.5 圖中的中文與標註

1. **圖內只放拉丁字母、數字與數學符號。** 這樣不依賴 CJK 字型，也不會有中英混排的間距問題。
2. **中文標註用原生 text 節點疊在圖上。** 用 `data_to_node(fig, ax, 節點x, 節點y, 資料x, 資料y)` 把圖上的資料座標換成頁面座標（實測誤差 < 1 像素），再放文字節點或 Connector 端點。
3. 一定要在座標範圍與長寬比都**定案之後**才呼叫 `data_to_node()`。
4. 圖的外框要預留中文標註的位置，標註不要壓在曲線上。

### 4.6 嵌入方式與大小預算

**這一節明確覆寫格式規格書的一條建議。** 格式規格書建議 agent 只用 `http(s)` 網址、不要塞 base64。但 agent 無法上傳檔案，而 matplotlib 圖必須嵌入。本規範的規則是：

- **只有 matplotlib 產生的圖**，才可以用 `data:image/svg+xml;base64,…` 當 `image.src`。
- 實測依據：App 的原始碼說明內嵌 `data:` 網址是仍然支援的格式；專案的 `validateDocument()` 與匯入解析器都接受它；它只要求 `src` 非空。

| 項目 | 上限 |
|---|---|
| 單張 SVG | ≤ 250 KB（`svg_data_uri()` 超過會報錯） |
| 每頁圖片數 | ≤ 2 張 |
| 整份 page spec | ≤ 1 MB |

超過預算時：簡化圖（減少點數、去掉格線）、對密集圖層用 `rasterized=True`，或改輸出 PNG 並降低 dpi。

image 節點的欄位：

```json
{
  "type": "image",
  "image": { "src": "data:image/svg+xml;base64,…", "alt": "…", "fit": "contain" },
  "text": "<與 alt 相同>"
}
```

- `alt` **必填**，寫出圖「顯示了什麼」，不要寫「示意圖」。
- `fit` 固定 `contain`，節點框的長寬比必須等於 `figsize` 的長寬比。

### 4.7 每張圖的自我檢查清單

- [ ] 判定用 matplotlib 的理由成立（位置、大小、角度或形狀承載資訊）
- [ ] 所有座標由公式計算，沒有手填
- [ ] 涉及方向、角度時有 `set_aspect("equal")`
- [ ] 公式用 mathtext，沒有亂碼或缺字
- [ ] 圖內沒有中文，中文標註是疊上去的原生文字
- [ ] `svg_data_uri()` 沒有報錯（沒有被切掉、沒有活的 `<text>`、沒有外部資源、沒超過大小）
- [ ] **轉成 PNG 親眼看過一次**（確認圖例沒壓到曲線、標籤沒擠在一起、顏色對得上 2.1）
- [ ] 圖中的數字與正文完全一致
- [ ] `alt` 描述了圖的內容

### 4.8 待驗證項目

這些在目前環境無法確認，請在 App 裡試一次：

1. SVG data URI 的 image 節點在畫布上是否正常顯示、縮放是否清晰。
2. **Export PDF** 輸出時，SVG 圖是否正常（專案用 `modern-screenshot` 加 `jspdf` 截圖，行為未驗證）。
3. 在播放器（Player）裡是否正常。

若任一項失敗，退路是把同一張圖輸出成 PNG（`fig.savefig(format="png", dpi=200)`），其餘規範不變。

## 5. 工作流程

1. **讀文本，列出候選頁面**，每頁寫一句「這頁要回答什麼」（1.1）。
2. **套用拆頁條件**（1.4），決定頁數與頁型序列（1.5）。
3. **為每一頁選主版型**（3.3），檢查相鄰頁不重複（3.4）。
4. **決定色彩角色**（2.1），在第一頁就固定下來。
5. **需要精確圖形的頁面**，按第 4 節產生 SVG 並嵌入。
6. **產生 page spec**，每頁一份，node id 用不同前綴。
7. **自動檢查**：邊界範圍、文字是否溢出、文字與合成背景的對比、node id 不重複、Connector 標籤深色。
8. **（有條件時）用專案原始碼的 `insertPageAsStep()` 與 `validateDocument()` 實跑**。
9. **交付時說明**：拆頁依據、每頁的版型與配色語意、哪些項目尚未實測。
