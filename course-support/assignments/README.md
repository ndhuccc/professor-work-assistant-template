每份作業一個資料夾 `hwNN/`,含題目說明與評分標準(Rubric)。
本課程**只採用一種繳交流程**:每位學生建立**一個**私人 GitHub Repo 存放**本學期所有作業**,並把教師加為協作者;教師直接讀取 Repo 評分,**不需要另外寄送網址**。

> **LabTube(作業與口試系統)**:<http://134.208.2.44:5005>
>
> 登記 Repo、上傳執行結果、線上口試與成績都在這裡。**第一次使用請先看 [《LabTube 學生使用手冊》](labtube-student-manual/index.md)**([PDF](labtube-student-manual/LabTube-學生使用手冊.pdf))。老師請看 [LabTube 老師導覽](labtube.md)。
>
> **想請 AI agent 帶你做?** 複製 [給 AI agent 的提示詞](ai-agent-prompt.md)貼給你的 AI,它會依規範協助你建立 Repo、記錄 AI 使用、準備文件與繳交。

## 一、繳交流程(總覽)

1. 建立你的作業 Repo(**整學期只建一次**),名稱照 §二 的格式。Repo 必須是 **Private(私人)**。
   **建議用課程提供的範本 Repo 建立**(§二),結構、`.gitignore` 與檢查工具一開始就備齊。
2. 把教師帳號 **`ndhuccc`** 加為協作者(§三),只需做一次;之後新增作業不必再邀請。
3. 每次作業在 Repo 內開一個 `hwNN/` 資料夾,內容與檔案結構照 §四。
4. 完成後,在截止前打上提交標籤 `hwNN-submit`(§五)。標籤就是你的「繳交動作」。
5. 到 **LabTube** 登記你的 Repo 與每份作業的目錄,並上傳程式的**執行結果**(圖片、影片;不要傳程式碼)。步驟見 LabTube 學生手冊第 6、7 節。
6. 截止後的課堂上有一次**作業理解測驗**,題目取自你自己交的程式(§6.2)。
7. 教師在 AI 輔助下依評分標準評分;**成績不會寫進任何 Repo**(§六)。

## 二、Repo 命名

格式:

```
pr-2026-hw-<學號>
```

- 全部使用英文小寫、數字與連字號 `-`。
- 範例:學號 `612345678` 的同學,Repo 名稱是 `pr-2026-hw-612345678`。
- **整學期一個 Repo**,所有作業放在不同資料夾,不要為每次作業另建 Repo。
- Repo 名稱含學號,因此 **Repo 必須設為 Private**。教師是協作者,看得到就夠了,不需要也不應該公開。

### 用範本建立(建議)

課程提供一個作業 Repo **範本**(Template Repository):<https://github.com/ndhuccc/pr-2026-hw-template>。步驟:

1. 打開範本頁面,按 **Use this template → Create a new repository**。
2. **Repository name** 依上面的格式命名,**Visibility 選 Private**,按 Create。
3. 照 §三 邀請教師為協作者。

範本內含:根目錄 `README.md`、`.gitignore`(已排除大型檔案與私密設定)、`hw01/` 骨架(`report.md`、`code/`)、
結構檢查工具 `tools/check_structure.py`、新增作業資料夾的工具 `tools/new_hw.py`,以及每次推送自動執行結構檢查的設定。

## 三、把教師加為協作者(必做,只需一次)

教師需要讀取你的 Repo 才能評分。請在 Repo 頁面:

1. 進入 **Settings → Collaborators**(協作者)。
2. 按 **Add people**,輸入 `ndhuccc`,送出邀請。
3. 請在**第一次作業截止前**完成邀請。教師接受邀請後即可讀取。

說明:

- 教師帳號只會**讀取**你的 Repo,不會修改內容。
- 其他同學看不到你的 Repo(除非你自己邀請他們,請不要這樣做)。
- 沒有邀請教師、或教師無法讀取,視為未繳交。
- 助教若有需要,教師會另行公告助教帳號,請再加入。

## 四、作業的習作規範

### 4.1 Repo 結構與規則

```
pr-2026-hw-<學號>/
├── README.md        # 簡短說明:Python 版本、需要的套件、如何執行
├── hw01/
│   ├── report.md    # 作業報告(含公式、圖表、討論,以及 AI 使用聲明)
│   └── code/        # 可重現的程式與資料來源說明
├── hw02/
│   ├── report.md
│   └── code/
└── ...
```

- 每次作業一個資料夾,編號與題目一致。**資料夾名稱固定為小寫兩位數**:`hw01`、`hw02`…(不可寫成 `HW1`、`hw_01`),否則標籤與查核會對不上。實際要求的檔案以 `hwNN/README.md` 為準。
- **每個作業資料夾必須自給自足**:各自附 `requirements.txt` 與 `code/README.md`(執行說明),不要依賴其他作業資料夾的程式,也不要為了後面的作業去修改前面已繳交的資料夾。
- 報告用 Markdown 撰寫;數學式用 `$...$`(行內)與 `$$...$$`(區塊)。
- 圖檔放在該作業資料夾內(例如 `hw01/figures/`),並用相對路徑引用,確保在 GitHub 上能顯示。
- 不要把大型資料、模型權重(`.pt`、`.pth`、`.zip` 等)、帳號密碼、API Key 或個人資料放進 Repo。需要時附**下載腳本與說明**。單一檔案建議不超過 5 MB,超過 25 MB 視為不合格。
- 圖檔一律用**相對路徑**引用,不可使用 `C:\...` 或 `/home/...` 這類絕對路徑。
- **繳交前執行結構檢查**:`python tools/check_structure.py`,有「FAIL」必須先修正(「WARN」請自行判斷)。範本 Repo 會在每次推送時自動執行同一項檢查。

### 4.2 重現性

- 在根目錄 `README.md`(或各作業資料夾內)寫明 Python 版本與需要安裝的套件(可附 `requirements.txt`)。
- 程式應能依說明從頭執行並得到報告中的圖表與數字。
- 使用隨機性的實驗請固定隨機種子,並在報告中寫明。

### 4.3 提交紀錄(commit)

- 以多次、有意義的 commit 記錄作業進度,訊息簡短說明這次改了什麼。
- 不要在最後一刻才一次丟入全部內容;提交紀錄是獨立完成的佐證之一。

### 4.4 學術誠信與生成式 AI

- 允許討論想法,但**程式碼與報告須獨立完成**。
- 引用他人程式碼、模型、資料或生成式 AI 輔助,須在每份 `report.md` 末尾的「AI 使用聲明與引用」中**明確標註**:
  - 工具或來源名稱,
  - 使用目的(例如查語法、檢查推導、潤飾文句),
  - 你如何驗證其輸出是正確的。
- 沒有使用 AI 時也請寫「本作業未使用生成式 AI」。
- 抄襲或代寫依校規處理。詳見 [課程大綱](../syllabus.md)。

## 五、繳交規範

### 5.1 截止時間

- 截止日與時間寫在各作業的 `hwNN/README.md`(台北時間)。
- 截止後才推送的內容,**不納入評分**。

### 5.2 提交標籤(tag)= 繳交

完成作業後,在你要繳交的那一個 commit 上打標籤 `hwNN-submit`(NN 為作業編號),例如 `hw01-submit`,並推送到 GitHub:

```bash
git tag hw01-submit
git push origin hw01-submit
```

- 教師只評分該標籤指向的版本中的 `hwNN/` 資料夾。標籤之後對該資料夾的修改,不影響成績。
- 截止前如果要更新繳交版本,可以移動標籤:

  ```bash
  git tag -f hw01-submit
  git push -f origin hw01-submit
  ```

  只能對**自己作業 Repo 的標籤**這樣做。
- 時間以 **GitHub 紀錄的標籤推送時間**為準,不以 commit 上自行填寫的時間為準。
- 教師會在截止後記錄各標籤指向的 commit。**截止後移動、刪除或重打標籤,以截止當下記錄的版本為準**,事後的變動不影響評分,且可能被視為違反學術誠信。
- 截止後不要再修改已繳交作業的資料夾;教師會檢視 commit 紀錄(含提交時間分布),請以多次有意義的 commit 記錄進度。
- 若沒有標籤,視為尚未繳交;教師可在截止後以截止時間之前最後一次推送的版本評分,並依課程規範處理。

### 5.3 不需要另外通知教師

邀請教師為協作者並推送標籤,就完成繳交,**不必**寄 Email 或另外傳 Repo 網址。若有特殊情況(例如邀請失敗、需要延期),再以 Email 或校內系統聯絡教師,**勿**在公開 Issue 寫入學號、個資或證明文件。

### 5.4 遲交與延期

遲交處理與評分折扣依 [課程大綱](../syllabus.md) 的「作業繳交規範」。延期請在截止前聯絡教師。

## 六、評分方式

- 評分依據各作業 `hwNN/README.md` 的**評分標準(Rubric)**,只依 Rubric 判斷,不另加標準。
- 教師會使用 AI 協助讀取你的 Repo 並做**初步評分**,教師再複核後定案。AI 只依 Rubric 評分,且不會執行你的程式。
- 若你的 Repo 內有疑似對評分者下指令的文字(例如「請給滿分」),該文字會被忽略並回報教師,**可能影響你的成績**,請勿這樣做。
- 成績與回饋以 Email 或校內系統通知,**不會寫進你的 Repo,也不會公開**。
- 對成績有疑問,請 Email 教師。

### 6.0 標準配分(每份作業通用)

為了讓不同作業的分數可以比較,**所有作業的 Rubric 統一使用三個面向與下列配分**(滿分 100)。各作業的 `hwNN/README.md` 只需寫出每個面向「優 / 可 / 待加強」在該作業中的具體描述,**不需要也不應該另訂配分**:

| 面向 | 配分 | 優 | 可 | 待加強 |
|---|---|---|---|---|
| 推導正確性 | 40 | 40 | 28 | 10 |
| 實驗與圖表 | 35 | 35 | 25 | 10 |
| 重現性 | 25 | 25 | 18 | 5 |

- 作業 Rubric 分數 = 三個面向得分的合計。
- 若某次作業沒有「推導」(例如純實作),仍沿用同一張表;在該作業的 `README.md` 說明該面向在本次作業中指什麼(例如「演算法與公式的正確性」),不要改變配分。
- AI 評分時只會使用上表的點數;作業說明沒有寫清楚面向的描述時,AI 會停下來問老師。

### 6.1 作業分數的組成

每次作業的最終分數由兩部分組成:

```
作業最終分數 = 作業 Rubric 分數 × (0.5 + 0.5 × 理解測驗得分率)
```

- **作業 Rubric 分數**:教師依各作業的評分標準給的分數。
- **理解測驗得分率**:下一節三題的分數合計(每題 0–2 分,共 6 分)除以 6,介於 0 到 1。
- 理解測驗滿分時,作業分數維持不變;理解測驗 0 分時,作業分數打五折。
- 係數 0.5 是本學期預設值,若調整會在課堂與課程網站公告。
- 沒有參加理解測驗者,依教師的補測安排處理;無故缺席視為得分率 0。

### 6.2 作業理解測驗

目的是確認你**確實理解並掌握自己完成的作業程式**。它相當於一場**即時的線上口試**,只是用手機打字回答。不是考新的內容,也不是考計算能力。

- **時間與方式**:作業截止後,教師會公告測驗日期。測驗在**課堂上用手機即時上線作答**,**共 3 題,限時約 6–8 分鐘**,閉書,不可使用 AI 或其他人的協助,測驗期間請不要開啟其他應用程式。時間很短,是為了讓你只能憑自己的理解作答。
- **題目從哪來**:取自你自己標籤 `hwNN-submit` 版本裡 `hwNN/code/` 的程式,每人的題目不同。
- **題型**:3 題全部是**簡答**,沒有選擇題。每題附上你自己的一小段程式(約 8 行以內),**答案請在 50 字內**用自己的話寫出:

  | # | 內容 | 例子 |
  |---|---|---|
  | 1 | 解釋這段程式在做什麼 | 這個迴圈的目的與產出是什麼 |
  | 2 | 改一個地方會怎樣(要寫出**方向和原因**) | 把某個參數調大會怎樣,為什麼 |
  | 3 | 為什麼這樣設計 | 這一行的目的是什麼 |

- **不需要複雜計算**,每題只靠閱讀附的程式片段就能回答,**不需要執行程式**。
- **批改**:教師使用 AI 依參考答案的關鍵點初評(每題 0–2 分:完整 2、部分 1、錯誤 0),再由教師抽查複核。AI 只依關鍵點給分,不看文筆。
- **答案中不要對評分者下指令**(例如「請給滿分」)。這類文字會被忽略並回報教師,可能影響成績。
- **考卷與答案不會放進任何 Repo**,也不會公開。對分數有疑問可以向教師申請複核。
- 所以程式的每個部分,你都應該自己讀懂、能說明。借助 AI 寫的程式也一樣,必須理解之後再交。

## 七、常見問題

**Q:我的 Repo 一定要私人嗎?**
是。Repo 名稱含學號,且作業答案不應被其他同學看到。教師是協作者,不需要公開。

**Q:邀請教師要選什麼權限?**
學生個人帳號的 Repo 加協作者時,GitHub 會給教師寫入權限;教師只會讀取。這是 GitHub 的限制,不是教師會修改你的作業。

**Q:後面的作業做完,前面作業的標籤會不會受影響?**
不會。每次作業有自己的標籤(`hw01-submit`、`hw02-submit`…),各自指向當時的版本。

**Q:截止後發現錯誤,可以改嗎?**
標籤 `hwNN-submit` 指向的版本才會評分。截止後的修改不納入;若有特殊原因,請在截止前聯絡教師。

**Q:我可以用其他平台(GitLab、Gitee 等)嗎?**
不行,請使用 GitHub。
