# 來源、內容與交付驗證

## 來源紀錄

每一項重要結論至少記錄：來源 ID、文件名、服務／主機、完整路徑或穩定 URL、頁碼／段落／儲存格／投影片、版本／commit、查核時間及存取狀態。
原始文件明寫的事標「已核實」；依證據判斷標「推論」並解釋依據；來源缺失、工具不支援或證據不足標「無法驗證」。
commit 自填日期不等於遠端推送時間；找不到 commit 不等於沒有工作。保存正式截止日原文及時區，不把示範日期或週次窗口當成正式期限。

## 教材內容

建立來源 → 核心概念 → 講義檔案 → 投影片頁次 → 圖解／漫畫的覆蓋表。
核對定義、假設、符號、維度、推導、例子與結論；新增教學例子標示為補充。
數值例子實算並交叉檢查，單位、正負號、機率範圍、邊界條件必須一致。不得省略造成結論改變的前提。
引用只使用實際讀過且支持該結論的來源；長篇來源不整段複製，尊重其授權。

## 視覺與互動

- 逐頁檢查文字與文字、圖形、公式、按鈕、圖例之間的重疊、遮擋、截切及溢出。
- 至少檢查 1280×720、1920×1080 的簡報畫面；閱讀網頁另檢查 390px 寬與放大至 200% 的情況。記錄實際測過的尺寸，不能照抄為通過。
- 檢查公式是否真的渲染，沒有裸露 LaTeX、意外換行字元、缺字或錯誤上下標。
- Canvas 使用容器尺寸與裝置像素比設定繪圖解析度；重算座標以避免縮放漂移。先載入字型／數學引擎再量測，避免初始化時機錯誤。
- 檢查標籤、箭頭方向、決策線、色碼、對比與圖例；中文需要合適字型 fallback。
- 實際操作滑桿、按鈕、重設及邊界值；檢查縮放與視窗尺寸改變後狀態。
- 外部 CDN 資源記錄依賴；離線驗證失敗就不能宣稱完全離線可用。必要時在授權範圍內附本地資源及授權說明。
- 圖片連結逐一驗證，生成圖像檢查文字可讀性及概念正確性。

## 驗證報告

使用 templates/validation-report.md；每項只能填「通過、警告、失敗、未執行、不適用」，並附方法、證據及修復／下一步。
有失敗不得列為驗收完成；缺必要工具列「部分完成」，並交付可用的部分。靜態檢查與目視檢查分開。
壓縮包須解壓縮到新目錄，檢查檔案清單與連結；有 GitHub 發布時再查核實際 commit、Actions 與部署 URL。
