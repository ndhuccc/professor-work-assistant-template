# OnlineQuiz 命題與題庫匯入程序

範本整合版：0.3.1；來源增補包：1.0；查核：2026-10-17，Asia/Taipei。
所有 scripts/ 指令均從本範本根目錄執行；產出寫到使用者核准、Git 工作樹以外的教師私人目錄。
範圍：教授工作助理的一般課堂測驗。若指定 PR／IDL，另讀該課最新規範；不混用學生個人化三題簡答的 assignment-quiz 程序。

## 0. 先辨認執行階段

- 「加入工作指令」：準備此程序與可重用工具，不自行命題、不匯入、不修改遠端設定。
- 「幫我命題」：執行來源與命題階段，完成可供審閱成果。
- 「準備匯入」：完成實際 JSON、驗證報告與匯入預覽；並非已授權對外寫入。
- 「同意依預覽匯入」：僅對該已列明站台、題庫版本及檔案執行新增，完成後查核。

## 1. 載入命題技能與相依資料

正式來源：ndhuccc/claude-skills-pipelines 的 skills/bloom-exam-designer/。不要使用 skills/.trash/ 或 synced/ 的舊副本。
啟用技能：.agents/skills/bloom-exam-designer/SKILL.md，連同該技能 references/ 的兩份原文。原始入口另存 vendor/original-entries/bloom-exam-designer/SOURCE.md；原增補包完整保存在 integrations/onlinequiz/source-package/。
核對版本見 config/source-bundle.json；原增補包來源表見 integrations/onlinequiz/source-package/references/source-manifest.json。先完整讀取技能與兩份參考資料，再執行 Phase 0–3、Phase 5。HTML 僅教授另有要求才生成。
無法取得技能及快照時停止命題，指出缺少的檔案，不宣稱已使用技能。

## 2. 取得教授的素材與規格

輸入可為主題、貼文、教材檔或教材網址；多種來源可合併，但逐項記錄：
來源 ID、題名、作者／機構（可知時）、URL 或檔案定位、章節／頁碼／段落、取得時間與讀取狀態。
- 只有主題：提出知識範圍及參考來源；需要查核的專門事實以官方教材、原論文等一手來源確認。若課程版本不明，不冒稱符合指定教材。
- 文本：以教授提供內容為範圍；補充內容另標示。
- 網址：實際開啟、閱讀指定章節；必要時讀公式圖片／PDF。頁面標題或搜尋摘要不等於正文。
- 無法讀取、付費牆或頁面缺漏：說明涵蓋範圍，請教授補正文或檔案；不得假造內容。
- 教材可能含錯誤時，列出與推導或其他可靠來源的衝突，不能直接照抄。

蒐集題數、受眾、題型、Bloom 分布、配分、單題時間、語言、題庫名稱；目的站台可待匯入階段補。
未指定時提出技能預設：10 題、多選、大二理工、25 分鐘；雙語 JSON 與逐選項解析沿用技能規格。
技能百分比轉整數時，先採最大餘數法使總題數吻合，平手依記憶→理解→應用→分析→評鑑→創造順序，並呈現實際分配；10 題為 1/1/3/3/1/1。教授可調整。
全卷時間與單題時間不同；若 10 題共 25 分鐘，平均每題 150 秒僅為建議，不能默用系統預設 60 秒並聲稱總時長 25 分鐘。還需說明純自動模式每題收尾約 3 秒及網路延遲。
實際匯入前明確確認統一配分與計時；現有匯入格式只接受題庫層級 default_points / default_timer_seconds，無逐題配分或秒數欄位。若各題需求不同，提出拆題庫或另行修改系統的選項，不偷偷丟棄設定。

## 3. 先產出命題藍圖

依技能 Phase 1，列核心知識點、重要性、覆蓋題號、來源定位、Bloom 層次與動詞、必要的認知操作、題型、預計作答時間。
標註未覆蓋的重要知識點。以繁體中文解釋「記憶／理解／應用／分析／評鑑／創造」各測什麼。
呈現藍圖並等教授確認；教授已明示直接做或採用既定藍圖時不重複詢問。
可審閱草稿須標 DRAFT，不把藍圖確認當成實際匯入核准。

## 4. 命題、解析、品質報告

依技能 Phase 2–3 完成每題：
- 題幹、選項、正確答案、逐選項正誤推理、迷思剖析、Bloom 原則吻合說明、來源 ID／段落。
- 自行重新推導、檢查邊界條件、數值及單位；不得用「看起來正確」代替驗算。
- 中英對照的答案與條件一致；公式用 $...$ 或 $$...$$；JSON 由序列化工具產生，反斜線正確跳脫。
- 單選恰有一個正解；多選的所有選項獨立判斷，正解集合固定。若存在「多組替代答案均可得滿分」，現有 correct_answer 無法表示，須改編或標不相容。
- OnlineQuiz 會對每位學生打亂選項。禁止「以上皆是／以上皆非」、題幹或選項依賴「選項 A／B／第三項」等位置指涉；改為直接寫出敘述。解析應附選項原文或含義，不能只寫字母。
- 不因題目很難就標分析；識別既有方案不自動等於創造。若只有評估方案的證據，保守標評鑑；不能捏造學生已展示創造能力。
- 技能的難度／鑑別度指數屬命題前預測，明寫「未經施測的專家預估」。無實測資料不得稱已證實高鑑別度；沒有依據時標未估計並說明。技能中的猜對機率說法不可無條件當成實證。
- 品質報告包含實際 Bloom 分布、覆蓋缺口、逐題吻合理由、答案驗證結果、語言與公式檢查、未驗證事項。

輸出各自獨立：
1. 命題藍圖。
2. 教師版（答案、完整推理及逐選項解析）。
3. 學生版（只有題幹與選項，移除解答及洩題提示）。
4. 品質報告及每題來源對照。
5. OnlineQuiz 匯入 JSON（教師專用，含正解）。
6. 匯入預覽與驗證報告。

## 5. 轉換為 OnlineQuiz JSON

以 OnlineQuiz-v2 的實際 schemas.py、import_json.py 為準，說明文件可能落後。
採完整物件而非純題目陣列，才能明確保留題庫名稱與預設值：

```json
{
  "name": "課程-主題-日期-v1",
  "description": "教授核准的測驗範圍",
  "default_points": 1,
  "default_timer_seconds": 150,
  "questions": [
    {
      "node": "知識點中文 (English)",
      "question_type": "Analysis",
      "format": "Multiple Choice",
      "question": "雙語題幹",
      "options": ["雙語選項一", "雙語選項二", "雙語選項三"],
      "correct_answer": "AC",
      "explanation": "中文及英文完整解析，逐項說明正誤"
    }
  ]
}
```

上例僅為結構示意，不能作為正式考題匯入。
- 技能 Phase 5 已輸出逐題欄位；轉換只在外層包裝 name、description、default_points、default_timer_seconds、questions。
- node 存成 category；question_type 存成 question_type_tag。記憶→Knowledge、理解→Comprehension、應用計算→Calculation、應用操作→Implementation、分析→Analysis、評鑑→Evaluation、創造→Creation。
- format 只能是 Single Choice 或 Multiple Choice；每題 2–10 個非空選項，位置依序 A–J，正解為唯一大寫字母串，如 A、ACD。
- 不把 Bloom 品質報告／教師批註混進題幹或學生可見欄位。來源及品質資訊放教師側對照檔；不可假設未支援 JSON 欄位會被保存。
- 實際後端允許無字母選項，字母依陣列順序決定；舊 A. 前綴可相容。工具會拒絕錯位前綴，避免答案錯配。
- 為避免後端將整段 [...] 當包裝剝除，方括號本身若是題意必要部分，加入正常敘述或以 LaTeX 表達並檢查畫面。

離線準備（不連網、不匯入）：
```powershell
python scripts/prepare_onlinequiz_bank.py bloom-output.json --name "課程-主題-20261017-v1" --points 1 --seconds 150 --expected-count 10 --output onlinequiz-bank.json
python scripts/prepare_onlinequiz_bank.py onlinequiz-bank.json --expected-count 10
```

輸出檔已存在時工具拒絕覆寫；用新版本檔名。報告中的 SHA-256 必須是最後待匯入檔案的實際 bytes。
在指定 OnlineQuiz 工作副本可執行時，另用當前 ImportPayload.model_validate 及 validate_question_row 做不寫 DB 的相容性驗證。若依賴或副本不可得，標記「原生驗證未執行」，不以離線工具取代此事實。
另可執行 `python scripts/validate_onlinequiz_bank.py onlinequiz-bank.json --expected-count 10`。此工具使用已內附、固定版本的原始 schema 及純逐題驗證函式，需 Pydantic 2；不載入 Django ORM、不連線、不寫資料庫，不能代替完整站台驗證。必要時依目前使用者授權安裝 integrations/onlinequiz/requirements.txt。
所有公式在實際 KaTeX 環境目視查核；未執行就標未驗證。

## 6. 特別確認：計分政策

本範本依 OnlineQuiz-v2@32e27e422148e32c909f26a7b6f4cc5651bba5d4 的原碼快照說明規則；此流程不改動線上計分設定。

| 情況 | 現行 OnlineQuiz 規則 |
|---|---|
| 未勾任何選項，含逾時空白 | 一律 0 分 |
| 單選題 | 選答集合與正解集合完全一致才得滿分；錯選或多選均 0 分 |
| 多選題，已勾至少一項 | max(0, (n - 2k)/n) × 題目配分；n 為全部選項數，k 為選答與正解集合的差異數 |

四選一、滿分 10 分：空白 0 分、選對 10 分、選錯 0 分。多選四選項、正解為三項，若只選對其中兩項且無誤選，k=1，得 5 分；全對得 10 分，空白仍為 0 分。
實際題型由後端傳入 is_multiple；不要僅依正解個數推論題型。多選題即使只有一個正解，已作答時仍使用多選公式。

Bloom 技能的可選 HTML 計分，分母為正確選項數；與 OnlineQuiz 多選的分母及扣分方式不同。匯入預覽應明列實際題型、配分、計時及現行規則；若教授另有計分政策，先指出差異並確認，不能宣稱匯入會改變服務計分。
新版後端匯入預設單題時間為 60 秒，本範本轉檔工具已同步；明確傳入 --seconds 或 JSON 的 default_timer_seconds 優先。10 題全卷 25 分鐘仍需另行規劃，例如每題 150 秒，不能由 60 秒預設推論總時間。
Repo 已更新不代表指定站台已部署。正式施測前核對實際部署版本與設定；原附檔 source-package/ 的舊計分說明僅供歷史追溯。

## 7. 實際匯入前的具體預覽

先完成檔案及可執行的驗證，再列：
- 對象：指定 OnlineQuiz 站台完整 URL、實例／課程、操作者身分；GitHub Repo 名稱不是站台 URL。
- 內容：題庫名與版本、題數、題型／Bloom 分布、配分／秒數、檔名、SHA-256、答案與解析的可見範圍。
- 影響：新增資料庫題庫；不修改既有題庫、不開測驗；若伺服器可被學生存取，指出當前端點權限／提早揭露解析問題尚未驗收修正。
- 檢查：來源完整度、格式／原生驗證／公式畫面／答案查核，各自通過、失敗、未執行；計分差異決策；重複題庫檢查。
- 等教授確認具體對象、內容及影響。獲准後不重複索取同一核准；檔案變更導致 SHA 不同或站台變更則需重新呈現差異。

若站台無法連線，先交付 JSON 與報告，標「已準備，待匯入」，不要求教授公開私人站台或弱化權限。
不得藉由 API 端點目前缺少驗證而繞過教師登入。先使用正常教師介面，或教授核准的受控環境及授權連線。

## 8. 執行及驗收

優先：教師題庫管理頁上傳完整 JSON。
若有經授權且可用 API，對 /api/question-banks/ POST 完整 JSON 物件（與 multipart 上傳路徑不同，不能將裸陣列當 JSON body）。
若教授指定受控主機及本機管理命令，可依當前 manage.py import_questions --help 執行；不得猜主機、路徑或憑證。
GitHub Connector 只能讀寫 Repo，不能因此直接寫入線上 SQLite；不上傳試題 JSON 到公開 Repo。

驗收：
1. 記錄回傳 bank_id、實際題庫名稱、時間、imported_count、error_count、errors。
2. 重新讀取教師題庫列表／明細，核對題數、首中末題、順序、題型、題幹、選項、配分與秒數。教師明細端點不回傳 is_correct，不能據此宣稱正解已驗證。
3. 正解儲存若無可讀取且授權的管理介面／DB，標「原始檔與匯入流程已查核；DB 正解未直接回讀」。不得為驗收而擅自開場施測或公開答案。
4. 僅當題數吻合、錯誤為零且讀回成功，標「已匯入並驗收（已列明未驗證項）」；部分成功標「部分匯入」，保留題目索引與錯誤。
5. 若 timeout 或回應不明，先查現有題庫再決定，不盲目重送造成重複。伺服器目前沒有同名自動覆蓋或可靠冪等保證；同名不代表相同內容。
6. 部分匯入後不自動刪庫重試，因目前刪題庫會刪關聯場次及答案。提出補救方案及影響，再取得核准。
7. 沒有實際 UI／API／管理命令成功證據，就不能回報「已匯入」。

## 9. 收尾與任務狀態

依實際證據使用：待規格／待藍圖確認／命題中／待教授審閱／格式驗證通過／待匯入授權／待連線／部分匯入／已匯入待驗收／已驗收。
報告列事項、來源（含技能及後端 SHA）、截止日（未指定寫未設定）、負責人、狀態、下一步、最後查核時間（Asia/Taipei）、證據狀態。
紀錄執行 Agent、輸入來源定位、教師版及 JSON 的實際保存位置與版本／SHA、匯入站台及 bank_id、錯誤與補救；憑證、token 不進報告。


## 10. 學生版與可選 HTML

學生版必須移除 correct_answer、explanation、品質報告與 JavaScript 中的正解集合。原技能的「學生版即時評分」需要教師核准揭露解答或採伺服器評分，不能與「不含答案」混為一談。包內舊驗證報告是歷史來源證據，不代表此次整合已完成測試；本次結果另列於 docs/ONLINEQUIZ-INTEGRATION.md。
