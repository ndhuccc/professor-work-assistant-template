# 任務紀錄、GitHub 同步與技能維護

主要程序：W12、W13。W12 可獨立記錄、查詢或交接，不需要 GitHub；W13 僅在明確要求倉庫／發布／技能維護時執行。
先遵循 [AGENTS.md](../AGENTS.md)、[發布規範](../docs/PUBLISHING.md)、[隱私契約](../docs/PRIVACY.md) 與 [品質契約](../docs/QUALITY.md)。

## 觸發與範圍

- W12：「記錄這項任務」「查上次誰處理哪個檔案」「交接未完成工作」。
- W13：「推送這批教材」「更新技能／來源快照」「準備發布或 PR」。
- 紀錄既有工作不代表授權執行紀錄裡的任務；推送不等於合併、部署、公開或改倉庫設定。

## 必要輸入

W12：實際交辦來源、操作類型（record／update／search／handoff）、任務 ID 或可辨認的既有紀錄、執行 Agent、時間證據、輸入輸出與目前使用者核准的紀錄目的地。
W13：owner/repo、分支／基準 commit、檔案與目標行為、現有工作樹、可用授權工具、是否包含 PR／合併／部署／倉庫設定及具體範圍。
缺目的地可先交草稿，不能自行建立外部資料庫或推測主機、帳號與公開範圍。

## 技能與工具

| 程序 | 必讀技能 | 工具與相依資料 |
|---|---|---|
| W12 | [mission-log](../.agents/skills/mission-log/SKILL.md) | schema、examples；使用 Notion 時另讀 notion 及實際目的地 schema |
| W13 | [repo-publish](../.agents/skills/repo-publish/SKILL.md) | Git／GitHub 工具、目標規範與發布證據 |

範本檢查由 [doctor.py](../scripts/doctor.py)、[verify_bundle.py](../scripts/verify_bundle.py) 及 tests 執行；新程序入口用 [read_workflow.py](../scripts/read_workflow.py) 實際讀入流程與主技能。
檢查工具不提供登入、寫入外部紀錄或自動部署權限。Private／Template 設定僅在目標及授權明確時查核／變更。

## 執行程序

### W12：任務紀錄與交接（可獨立執行）

1. 確認 record／update／search／handoff 與核准目的地；先讀原技能及其 schema。非敏感工程紀錄可使用忽略追蹤的 workspace/logs；學生、考題、評語等敏感內容與定位依私人輸出政策，不以 gitignore 代替存取控制。
2. 有 mission ID 就精確找原紀錄，否則以交辦來源、日期、Agent 與資產對應檢查候選；相似標題不自動合併。新的任務與事件使用穩定 ID，寫入結果不明時不重複建立。
3. 記下真實執行者、任務、狀態、執行起訖／時間來源／時區與可計算的耗時；建立每個輸入輸出的資產清單。資產需有檔名、格式、儲存主機／服務、精確路徑或穩定 URI、版本、可讀狀態及位置證據。
4. 執行平台不等於儲存主機；不得猜 CCCHOME／CCCOFFICE 等主機。未知位置記原因及找回方式，metadata incomplete 與任務完成狀態分開，不捏造完整路徑。
5. 更新前讀完整最新紀錄；共同歷史只追加事件，更正引用原事件並保留舊內容。欄位修補只改指定屬性；沒有原子版本防護時不整段覆寫共享頁面，也不因並行衝突擅自聯絡其他 Agent。
6. 保存錯誤、影響、修復嘗試與解決時間；成功後仍保留原失敗歷史。不得記帳密、token、含秘密的 URL 或不必要的私人全文。
7. 寫入後讀回 ID、事件、資產位置及先前歷史是否保留。逾時／結果不明先查精確 ID／事件，確認不存在才重試同一操作；無法確認則標保存不確定。
8. 搜尋時依 ID、期間、日期意義、Agent、檔名、儲存位置及狀態篩選，讀原紀錄並處理分頁／重複；只報所查範圍的結果，不把 top-k 無命中當成任務從未發生。
9. 交接保留實際完成內容、未決項、錯誤與可執行下一步，以及每個必要產物的來源與保存位置。搜尋／交接不自動恢復任務執行。

### W13：GitHub 同步、發布與技能更新

1. 讀目標倉庫最新規範，核對分支、遠端 head、工作樹與使用者未提交內容。先保存既有工作，只處理授權路徑；不要為自動化清除或強制覆蓋。
2. 完成本機可審閱變更，列目的、前後差異、相依檔與驗證結果。教材另依其流程完成內容及視覺稽核；評分／考題／研究私人檔不能藉發布程序繞過禁止入庫的界線。
3. 新增／維護工作程序時同步 AGENTS、config/workflows.json、docs/WORKFLOWS、workflows 文件、所用技能／腳本與必要測試。每個 Wxx 的 workflow_path 必須有效，別名解析到正式程序；未索引文件、斷鏈或錯誤技能對應先修正。
4. 更新來源快照時從明確的新 commit 複製原始位元組，更新 source-bundle 的 commit、blob SHA、位元組數及適配／歷史紀錄。保留原授權及原附件，不能把手改快照說成未改原件。若原工具介面／預設改變，同步說明、報告版本與相關驗證。
5. 在範本根目錄執行以下適用檢查；課程網站建置用該課工作副本的工具，不混用：

   ```sh
   python scripts/doctor.py --template
   python scripts/verify_bundle.py
   python -m unittest discover -s tests -v
   ```

6. 檢查實際待提交清單及差異中的個資、解答、憑證與授權。列清楚 owner/repo、分支、檔案、採直接推送或 PR、是否部署、對外影響與回復方式；沿用本次已具體核准的同一動作，缺授權時停在可審閱結果。
7. 依可用工具提交／推送；若目標在期間有新增提交，先重新讀取並比較，合併不相干變更或詢問衝突，不強制覆蓋他人工作。使用 ref 版本防護時在版本不符後先讀現況，不盲目重試。
8. 讀回 commit、實際檔案及必要設定；可比對 Git tree 以確認完整內容。若要求部署，另查 Actions／部署及實際網站；只有要求範本時查 is_template，Private 目標另核對 private。記錄實際狀態，不將 API 接受等同完成驗收。
9. 以 W12 保存交辦、版本、變更清單、驗證、遠端結果、阻礙與下一步；回報可核對連結及限制。

## 確認節點

外部紀錄目的地、分享對象與 GitHub 動作各有本次授權範圍；歷史來源內的許可不移轉。變更可見度、刪除、合併、部署及排程不由一般同步授權推定。
本次已指定對象、內容與動作時繼續，不反覆要求相同確認。無安全追加／版本防護工具時交付草稿與阻礙，不用整頁替換繞過。

## 輸出與驗收

W12 輸出穩定任務／事件 ID、已保存且已讀回／待驗證／僅草稿狀態、執行者、位置清單與 metadata 完整度。
W13 輸出實際分支／commit、變更與測試摘要、遠端讀回及按範圍驗證的部署／設定。未完成者附可恢復的本機版本與具體阻礙。
原始來源、他人修改與事件歷史被保留；檔案與紀錄可由指定位置找回；W01–W14 皆能經 reader 依序讀取 workflow 與主技能。

## 失敗處理與交接

權限、連線、版本衝突、內容錯誤分別記錄。推送失敗保留本機變更；外部結果不明先讀現況，避免重複建立 commit／PR／任務或通知。
誤刪共享歷史時依授權版本證據追加恢復並保留歸屬，不以還原舊整頁覆蓋新工作。交接列本機與遠端實際版本、未完成動作、核准範圍與恢復步驟，不把「已準備」寫成「已發布」。
